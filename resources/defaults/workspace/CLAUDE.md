# 项目总览

> 这是所有 Agent 都会读的文件。把“机器人项目”换成你的项目，补上一段话的目标和当前阶段。

本仓库是一个机器人研发项目的共享仓库，由四个专业 Agent 和用户共同维护：机械（mech）、电子（elec）、控制与嵌入式（firmware）、论文（paper）。每个 Agent 是独立的会话，彼此看不到对方的对话，只能通过这个仓库里的文件协作。

## 目录

| 目录 | 内容 | 谁写 |
| --- | --- | --- |
| `spec/` | 需求、系统框图、接口约定 `interfaces.md` | 改接口的那一方，需用户确认 |
| `mech/` | 机械笔记、导出的 STEP/STL、尺寸表 | 机械 |
| `elec/` | 原理图说明、引脚分配表 `pinmap.csv`、BOM、网络表 | 电子 |
| `firmware/` | PlatformIO 工程、控制算法、仿真脚本、日志 | 控制与嵌入式 |
| `paper/` | LaTeX 工程、图、参考文献 | 论文 |
| `handoff/` | 交接单：谁改了什么，谁需要跟着改 | 所有人 |
| `.nexus/` | Agent 的配置和提示词（管理软件读取） | 用户 |

Fusion 模型和嘉立创EDA 工程存在各自的软件里，仓库只放导出物和说明。

## 协作规则

1. **只写自己的目录。** 需要别的专业改东西时写交接单，不要直接改对方的文件。
2. **`spec/interfaces.md` 是跨专业事实的唯一出处。** 板子外形和安装孔（机械与电子）、引脚分配（电子与固件）、执行器和传感器参数（机械与控制）只在这里定义，别处引用它而不是另抄一份。
3. **谁改了接口，谁写交接单。** 改动 `spec/interfaces.md` 的同时，在 `handoff/` 按 `_template.md` 新建一张交接单，写明改了什么、谁需要跟进。
4. **跟进别人的交接单后登记。** 在交接单末尾的“跟进记录”追加一行；所有接收方都跟进后把 `status` 改成 `done`。
5. **不编造。** 查不到的引脚、尺寸、参数、数据、文献，如实说查不到并问用户。
6. **如实报告验证程度。** 区分“写完了”“编译/检查通过”“仿真验证过”“在硬件上验证过”。

每个任务结束后管理软件会自动提交一次 Git，提交信息以 `[agent id]` 开头，不需要自己提交。
